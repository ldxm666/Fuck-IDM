## 一、根因（实测，非推测）

### 1.1 现象链

```
守护把伪造序列号写进 HKLM\SOFTWARE\WOW6432Node\Internet Download Manager\Serial
        ↓
IDM 启动 → ~62 秒后注册校验判定该序列号为 counterfeit
        ↓
写 256 字节 REG_NONE 的 MData 到 CLSID 键，并调用 ExitProcess(0)
        ↓
用户看到：「一个假冒的序列号被用来注册 Internet Download Manager。IDM 正在退出...」
        ↓
守护发现 MData → 删除它 → 轮换序列号 → 回到第一步（自伤闭环）
```

### 1.2 三次独立复现 + 截图

| 时间 | 配置 | 结果 |
| --- | --- | --- |
| 01:00:46 | 伪造序列号 + hosts 全屏蔽 | **64.0s 写 MData，`IDMan.exe exited code=0`** |
| 00:38:43 | 伪造序列号 + 防火墙屏蔽单 IP | **62.0s 写 MData，exit 0** |
| 00:58:23 | **无**序列号 + hosts 全屏蔽 | **93s+ 存活，无 MData，无退出**（但弹注册框） |
| — | 用户截图 | 「假冒的序列号…IDM 正在退出…」 |

### 1.3 关键结论

1. **触发源是伪造序列号本身，不是网络**。hosts 已把 `internetdownloadmanager.com` / `secure.` / `register.` 全部劫持到 `0.0.0.0`（DNS 实测确认），tripwire 照样在 64 秒精准触发 ⇒ 判定是本地/缓存逻辑，不是实时联网。
2. **`MData` 是 tripwire 的载荷**（256 字节 `REG_NONE`），不是良性心跳。写入点后面 20 字节内就是 `RegFlushKey` + `ExitProcess(0)`。
3. **`MData` 所在的 GUID 是硬编码字面量，不是由 `scansk` 派生**。二进制里共 5 条 `Software\Classes\CLSID\{GUID}` 字面量，实测命中 `{79873CC5-3951-43ED-BDF9-D8759474B6FD}`（= `CRegistrationDlg` 存储）与 `{E6871B76-C3C8-44DD-B947-ABFFE144860D}`（= `CConfirm` 存储）。交接文档「必须遍历整棵 CLSID 树」的建议仍然正确（因为键可能新增），但「GUID 每次都会变」的解释是错的。
4. **`MData` 引用代码未加密**。文件里有 **19 处明文 `68 E4 D1 69 00`（`push 0x69D1E4`）**，19/19 各带一条 type-3 HIGHLOW 重定位。「代码在磁盘上加密、必须动态调试」的旧结论不成立——静态可达。

## 三、目标架构：三层，零守护

设计原则：**让「已破解」成为系统的自然稳态**，而不是需要反复施加的状态。

```
┌─ 层 A：注册状态（根因）────────────────────────────┐
│  不伪造序列号。删除 Serial/FName/LName/Email，     │
│  且永不写入。→ tripwire 无触发源（实测已验证）      │
├─ 层 B：二进制补丁（结构免疫）──────────────────────┤
│  P1..P4 保留 + P5 封死 4 处 tripwire 出口          │
│  + P6 静音 counterfeit 弹窗 + P7 静音伪造序列号弹窗  │
│  → 即使误入 counterfeit 分支也无法自杀/无法骚扰      │
├─ 层 C：防回退（无进程）────────────────────────────┤
│  IDMan.exe 文件系统 ACL 不可变 + hosts 屏蔽          │
│  → 官方更新包无法覆盖补丁；无计划任务、无常驻进程     │
└──────────────────────────────────────────────────┘
```

### 层 A — 注册状态：停止伪造（根因消除）

- 删除 `HKLM\SOFTWARE\WOW6432Node\Internet Download Manager` 下的 `Serial` / `FName` / `LName` / `Email`。
- 清掉 `{E6871B76-…}` 键下 `sub_51FFC0` 缓存的 `checkRes…` 判决值（XOR 派生名，整键清值最稳）。
- **绝不能恢复「伪造序列号」这条腿**：它会被 `update.cgi?sn=` 上传到 `secure.internetdownloadmanager.com`，被服务端标记 blocked 后写回 CLSID 键 ⇒ 变成每次启动真弹 counterfeit 并退出。b8 阶段的分析已经警告过这条路径，b15 的「四腿方案」把它重新引入了一遍。

**代价**：无序列号时 IDM 冷启动会弹一个「注册 Internet Download Manager」模态框。这是本方案唯一需要额外解决的点，见 §五。

三处是「`push 0; call dword ptr [ExitProcess]`」紧邻形态（`6a 00 ff 15 e8 54 69 00`，8 字节）。补丁把这一整段换成 **8×NOP**：

> ⚠️ **不要用 `add esp,4` + NOP！**（本文件初版曾如此写，**已作废**）W3 的分支 `je 0x52177A`（`0x521773` 处）
> **恰好直接跳到那个 `push` 上**，改 `add esp,4` 后该路径会弹掉从未压入的 4 字节 → 栈损坏 →
> IDM 在 ~61s 以 `0x80000003` 崩溃。**必须整段 8×NOP**（push 与 call 一起去掉才不改变栈状态）。

| 站点 | 补丁起点（VA / file） | 原始 8 字节 | 替换为 |
| --- | --- | --- | --- |
| W1 | `0x44DED4` / `0x4D2D4` | `6a 00 ff 15 e8 54 69 00` | `90 90 90 90 90 90 90 90` |
| W2 | `0x4676F9` / `0x66AF9` | `6a 00 ff 15 e8 54 69 00` | `90 90 90 90 90 90 90 90` |
| W3 | `0x52177A` / `0x120B7A` | `6a 00 ff 15 e8 54 69 00` | `90 90 90 90 90 90 90 90` |

W4 形态不同：它由 `jne` 直接跳到 `call`，**前面没有 `push`**，所以不能加 `add esp,4`（会造成栈失衡）。改为封死分支本身：

counterfeit 文案由消息派发器 `sub_451E30` 弹出（该函数经一张函数指针表 `0x6A0B24` 注册）。

### 层 C — 防回退（不用守护）

守护存在的唯一理由是「IDM 自动更新会覆盖补丁」。用**预防**替代**修补**，需要零进程：

- **(a) 文件不可变（**仅作收尾加固，见下方警告**）**：对 `C:\Program Files (x86)\Internet Download Manager\IDMan.exe` 设置 DENY 写/删 ACE（`Everyone` 拒绝 `Write, Delete`）。更新器无法替换该文件。
  - 施加：`icacls "…\IDMan.exe" /deny "*S-1-1-0:(WD,DE)"`
  - 回滚：`icacls "…\IDMan.exe" /remove:d "*S-1-1-0"`
  - > ⚠️ **致命副作用（已实测）**：加了 DENY(W,D) 后 **Frida spawn 会失败** ——
    > `frida.NotSupportedError: unable to spawn executable at '…\IDMan.exe': 0x00000005`，
    > 因为 **Frida 注入需要该 exe 的写权限**。
    > ⇒ **纪律**：**ACL 只能在全部动态观测 / 验证结束后施加**；任何需要 **Frida 注入或重新部署**的
    > 环节之前，**必须先** `icacls "<IDMan.exe>" /remove:d Everyone`。
    > **防自更新的第一层用 (b) hosts 屏蔽**，**(a) ACL 仅作收尾加固**。
    > 证据：`work/idm-6.43b8/logs/verify/lead-acl-remove.log`。
- **(b) hosts 屏蔽**（已实现）：`internetdownloadmanager.com` / `www.` / `secure.` / `register.` / `tonec.com` / `www.tonec.com` → `0.0.0.0`。域名级，抗 IP 漂移；同时杜绝伪造序列号被上报。
- **(c) 不要**再用「定时刷新 `LastCheckQU`」的机制——那是另一种守护。

**清理**：删除计划任务 `IDM-Activator-Guard`，删除 `HKCU\…\Run\IDM-Patch-Lockdown`（若有）。之后本机不应存在任何 IDM 相关常驻项。
