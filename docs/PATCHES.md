## P1 · `registration_flag` —— 注册状态全局

- **目标定位**：`.data` 静态初始化器，b15 = VA `0x77BD24` / file `0x379524`；b8 = VA `0x779CDC` / file `0x3782DC`
- **内部实现证据**：原值 `01 00 00 00`（非 0 = Trial）→ 改 `00 00 00 00`（0 = Full）。
  全 `.text` 45 处引用，**只有 2 处写**，且都是 `mov dword [flag], 0`（注册成功路径）⇒ **无代码能写回非 0**。
- **调用方分支验证**：「关于 IDM」判定点 `cmp dword [flag], ebx` / `je` → 0 走 `"Full"` 分支，
  1 走 `"Trial"`。弹窗总门控 `0x5BD4EA cmp dword [flag], 0` / `je` 在非 0 时才会走到 `push 0x14D8`。
  ⇒ 改 0 后两条分支同时走向「已注册」，且不引入任何 NPE 风险（纯数据初值修改）。
- **抗混淆锚点**：`cmp/je/push "Trial"/jmp/push "Full"` 指令形状 + `.data` 节可写性校验；
  字符串 `"Trial"` / `"Full"` 双引用交叉验证。

## P2 · `expiry_display_9999` —— 到期显示

- **目标定位**：字符串 `"%b/%d/%Y"`（全镜像唯一）→ `"%b/%d/9999"`（等长替换）。
- **内部实现证据**：该格式串交给 `strftime`，`9999` 作为**字面量**原样输出。
- **调用方分支验证**：全镜像共 3 处引用，已逐一核实**全部**是「许可证到期时间」显示，不影响其它日期。
- **抗混淆锚点**：`%b/%d/%Y` 字符串唯一性。
- ⚠️ **诚实说明**：IDM 的 `nExpDt` 是 **32 位 `time_t`**（读取时 `lpcbData=4`），硬上限 **2038-01-19**，
  9999 在该字段里结构上不可达。**真正保证「不过期」的是 P1，不是这个日期。**

## P3 · `trial_nag_kill` —— 试用弹窗函数置空

- **目标定位**：弹窗文案 `"This is 30 day trial version of Internet Download Manager"`
  → CString 初始化形状 → 函数入口 `int3` 边界。
- **内部实现证据**：把函数入口改成 `mov eax,1 ; ret`（等长覆盖）。
- **调用方分支验证**：调用方只判 `if (popup() != 0)` 走注册流程；返回 1 等价于「用户点了确定」，
  不改变任何后续状态机（这是**纵深防御**，P1 已从上游短路整条链）。
- **抗混淆锚点**：上述文案字面量（b15 已整段删除该文案，故 P3 在 b15 上通常不命中 —— 正常）。

## P4 · `counterfeit_guard` —— counterfeit 闸门封堵

- **目标定位**：`38 9D ?? ?? ?? ??`（`cmp byte ptr [ebp+disp32], bl`）+ `8D 95 ?? ?? ?? ??`（`lea edx,[ebp+disp32]`）
- **内部实现证据**：闸门函数内「校验失败 → 写 `MData` → `ExitProcess`」的分支，改为跳成功出口。
- **调用方分支验证**：改的是**函数内部**的分支，调用方拿到的返回值语义不变（0 = 通过），
  不会让调用方拿到 `null` 或异常值。
- **抗混淆锚点**：两条指令的 disp32 通配形状。

## P5 · `tripwire_exit_*` —— 封死 4 处自杀出口

- **目标定位**：全文件 7 处 `call [ExitProcess]`，其中 4 处属自杀路径（**必须与 `MData` 字符串做归属判别**）。
  形态 (a) `push 形态` 3 处 → 8×NOP；形态 (b) `branch 形态` 1 处
  （`80 BF disp32 00 75 rel8 C6 87 disp32 01`）。
- **内部实现证据**：直接封**出口**，而不是封入口 —— 因为 P4 只封住其中一条的入径，另外 3 条照样能杀进程。
- **调用方分支验证**：封出口后该路径变为「继续执行」，随后即函数返回；
  由于 P4/P7/P9 已让该路径不再被进入，实际是**冗余保险**。
- **抗混淆锚点**：导入表解析 `ExitProcess` 的 IAT 槽 + `MData` 字符串归属判别。

## P6 · `counterfeit_popup_*` / `license_popup_*` —— 弹窗调用静音

- **目标定位**：counterfeit 文案串 → CString 全局 → 弹窗派发器 `sub_451E30` 边界内的调用点。
- **内部实现证据**：调用点改为「自补清栈 + 返回 0」（`83 C4 10 31 C0 90` 形态）。
- **调用方分支验证**：stdcall 无调用方清栈，因此**必须自补**；否则栈失衡会立刻崩。
- **抗混淆锚点**：文案串 + 派发器函数边界（`int3` 对齐）+ 调用点数量上限。

## P7 · `counterfeit_broadcast` —— 封死广播线程

- **目标定位**：counterfeit 正文的**密文串**（单字节 XOR key `0x0F`）+ `push <密文>` 唯一性。
- **内部实现证据**：把广播 worker 入口改成 `xor eax,eax ; ret`（`31 C0 C3`）。
- **调用方分支验证**：worker 由线程启动，返回值无人使用；封死后线程不再弹框，主流程不受影响。
- **抗混淆锚点**：XOR 密文串（明文搜不到 —— 必须先做 256-key XOR 全扫）+ 宿主函数跨度 < `0x800` 的合理性校验。

## P8 · `grhlp_msgbox_*` —— `IDMGrHlp.exe` 弹窗静音

- **目标定位**：`IDMGrHlp.exe` 内两处 `MessageBoxA` 调用点（file `0x52A1` / `0x52C8`）。
- **内部实现证据**：两处均改为 `83 C4 10 31 C0 90`（`add esp,0x10 ; xor eax,eax ; nop`）。
- **调用方分支验证**：`MessageBoxA` 是 stdcall，被调方自己清栈；这里因为**调用点被替换**，
  所以要自补 `add esp,0x10`。返回值 0 等价于用户点了「否」，不改变后续状态机。
- **抗混淆锚点**：`MessageBoxA` 的 IAT 槽 + 调用点前后指令序列。
- **验证方式**：受控 A/B 对照（`IDMGrHlp_orig` vs `IDMGrHlp` patched）。
  ⚠️ 端到端为 INCONCLUSIVE —— 该 helper 在测试窗口内未被拉起，因此判据取 A/B 对照。

## P9 · `mdata_write_*` —— 封死 `MData` 写入

- **目标定位**：`MData` 字面量（file 内 19 处明文 `68 E4 D1 69 00`，19/19 带 type-3 HIGHLOW 重定位）。
- **内部实现证据**：封**写入调用点**，不封退出点（退出已由 P5 覆盖）。
- **调用方分支验证**：唯一保留的排除条件是**可达性** —— 落在 P4 已封入口的函数内的写入按不可达跳过。
- ⚠️ **两条硬教训**：
  1. 早期版本要求「调用点 +10 B 处必是 `RegFlushKey`」当锚点 —— 这个锚点**对 `sub_466EE0` 成立、对 `sub_521050` 不成立**，
     把 `0x120A54`（MData 真·活路径）判为假候选排除，造成漏点。
  2. **不要**用 `call [ExitProcess]` 当锚点：P5 施加后会把它打成 8×NOP，导致 P9 认不回自己（幂等被破坏）。
- ⚠️ **静态门控分析不能单独作为「死代码」判据**：曾据 `cmp eax,7DCh`(2012) 判定 `sub_521050` 三处 `MData` 写入为死代码，
  而动态实测（`t = 62.425 s`）证明活路径**正是那一处**。死代码结论必须有动态证据（断点命中 + 时刻 + 参数值三重对齐）。

## P10 · `longtext_popup_*` —— 长版弹窗显示端静音

- **目标定位**：`sub_474D20`（弹窗包装）的调用点 file `0x75444` / VA `0x476044`。
- **内部实现证据**：`E8 D7 EC FF FF`（`call`）→ `31 C0 90 90 90`（**禁止补清栈**，由调用方负责）。
- **调用方分支验证**：cdecl，`call` 之后调用方有 `add esp,0x10`；因此只替换 `call`、保留清栈。
- **抗混淆锚点**：前锚 = 调用点**之前 13 字节**的完整指令序列（与 P11 的前锚不同，故互不干扰）。
- **验证方式**：端到端 PASS（300 s `SURVIVED-WINDOW`，真实触发下载）。

## P11 · `latent_popup_*` —— 潜伏弹窗静音

- **目标定位**：与 P10 **同型**（同一包装 `0x474D20`、同 `uType 0x41030`、同 cdecl + 调用方 `add esp,0x10`），
  但**静态存在、当前场景未被触发**。
- **内部实现证据**：同 P10 的替换形态。
- **调用方分支验证**：同 P10。
- **状态**：预防性（**无法动态验证** —— 没有已知触发路径）。

## ~~P12~~ · `license_valid` —— 【RETIRED，实测否决】

- 改的是 `byte_788CF4`（file `0xEDBF7` / `0xEDC1F`，A+B 成对）。
- **否决证据**：手工热补丁 + 冷启动验证 ⇒ **注册框照旧弹 12/12**。
  根因：`byte_788CF4` 根本不是「决定弹注册框」的标志；注册框的门控在 `sub_451E30` 的 `cmp esi,ebx / je`（见 P13）。
- **处置**：**不进 `ALL_FINDERS`**，仅保留实现作为「被否证方案」的记录。**不要重新启用。**

## P13 · `registration_dialog_*` —— 启动路径注册框不创建

- **目标定位**：`sub_451E30` 内的注册框 case（file `0x4531D2` 一带）。
- **内部实现证据**：case 体置空 ⇒ 恒走「无需弹框」路径。
- **调用方分支验证**：修的是「点取消就退出」—— 门控 `cmp esi,ebx / je` 被短路后，
  不再创建对话框，也就不存在「取消 → 退出」这条路径。
- **抗混淆锚点**：注册框构造函数 `0x521C00` 的调用点上下文。

## P14 · `wrapper_shortcut_A/B` + `icontype_popup_*` —— wrapper 级短路

- **目标定位**：弹窗包装 `sub_474D20` 入口。file `0x74120`（VA `0x474D20`）跳 cave `0xEF2E4`。
- **内部实现证据**：
  - **A（跳板）**：入口 5 字节改 `jmp <cave>`；
  - **B（cave）**：`uType == 0x41030` ⇒ **裸 `ret` 返回 0**，其余 `uType` ⇒ 恢复原指令后跳回。
  - 另枚举 `uType == 0x41030` 的 4 个显示点（P10/P11 已覆盖的 2 处由按偏移去重收敛）。
- **调用方分支验证**：`sub_474D20` 全库 260 处调用，其中 `0x41030` 仅 **6 处**；
  其余 244 处走 cave 的「恢复原指令后跳回」路径 ⇒ **零影响**。
  返回值 0 = 「用户未确认」，与「点了否」语义一致。
- **抗混淆锚点**：`uType` 常量 `0x41030` + wrapper 入口字节序列 + cave 可用空间（`.text` 尾部对齐填充区）。
- ⚠️ **形态必须逐站点判定**：曾因「`call+5` 必须是 `83 c4 10`」这个过严锚点误拒 `0x75710`
  （它的清栈在 `call+0x0B`）。**锚点过严 = 假阴性，与过松 = 假阳性同样危险。**

## P15 · `download_reg_dialog_*` —— 下载路径注册框不创建

- **目标定位**：`IDMan.exe` file `0x94364` 一带的注册框 case 体。
- **内部实现证据**：case 体置空。
- **调用方分支验证**：浏览器点下载（真实用户路径）落在这里，与启动路径（P13）**是两条独立 case**，
  因此不能靠封「共同门控」（没有共同门控）。注册框构造函数 `0x521C00` 与 P13 相同。
- **抗混淆锚点**：兄弟 case 尾部 `B8 01 00 00 00 9B E9`（`mov eax,1 ; wait ; jmp rel32`）。

## （可选）`update_gate` —— 解除「升级前必须先注册」

- **目标定位**：更新对话框「现在更新」按钮的 `WM_COMMAND` 处理器内，
  `call [RegQueryValueExA]` / `test eax,eax` / `jne <弹「在升级 IDM 之前请注册」+ EndDialog>`。
- **内部实现证据**：把那条 `jne` 换成 6 个 NOP ⇒ 查不到 `Serial` 也走成功路径。
- **调用方分支验证**：序列号缓冲区在函数入口已 `memset` 成 0，查不到时是空串，
  拼出来就是 `"update.cgi?"`，**不会把未初始化栈数据带进 URL**。
- **默认关闭**：需要显式 `--allow-update`。
